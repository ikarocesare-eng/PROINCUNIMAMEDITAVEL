O que está pronto: layout, logo fornecida, campos do CMS, conteúdo demonstrativo e geração automática. O que depende da sua conta: criar/conectar o repositório, configurar OAuth e autorizar o primeiro login. O site mostrado no ChatGPT é uma prévia; não está conectado ao seu GitHub ou Netlify.

1. Publicar no Netlify

  1. Baixe o ZIP e extraia os arquivos no computador. Abra a pasta: nela devem aparecer package.json, netlify.toml, build.mjs, render.mjs, admin, data, content e assets.
  2. No GitHub, crie um repositório chamado, por exemplo, proinc-unimam. Pode ser privado. Se o site real já possui dados, faça uma cópia antes de substituir qualquer arquivo.
  3. Use Add file → Upload files e envie o conteúdo da pasta extraída, não o ZIP. Faça o commit na branch main. A raiz do repositório precisa conter netlify.toml, sem uma pasta adicional envolvendo tudo.
  4. No Netlify, escolha adicionar/importar um projeto existente, conecte o GitHub e selecione o repositório.
  5. Confirme as configurações da tabela abaixo. Elas já constam no arquivo netlify.toml.
  6. Nas variáveis de ambiente do projeto, adicione GITHUB_REPOSITORY com o valor SEU_USUARIO/proinc-unimam. Use o nome exato do seu usuário/organização e do repositório. Disponibilize a variável ao build de produção.
  7. Publique. Se adicionou a variável depois do primeiro deploy, execute um novo deploy. Abra o endereço https://seu-projeto.netlify.app e confira a página.

Não é necessário banco de dados. O CMS grava alterações no Git e o Netlify gera uma nova publicação. Arrastar somente o site pronto para o Netlify não estabelece essa conexão: use a integração com GitHub.

2. Ativar o login do painel

Esta versão usa Decap CMS com login GitHub. Você autentica na conta do GitHub; não há uma senha administrativa fixa no HTML. Os editores precisam ter permissão de escrita no repositório.

  1. Abra GitHub → Settings → Developer settings → OAuth Apps e clique em New OAuth App ou Register a new application.
  2. Preencha Application name: PROINC UNIMAM. Em Homepage URL, use o endereço de produção no Netlify.
  3. Em Authorization callback URL, informe exatamente https://api.netlify.com/auth/done.
  4. Registre o aplicativo. Copie o Client ID e gere um Client Secret.
  5. No projeto Netlify, abra Project configuration → Security → OAuth. Em Authentication Providers, clique em Install Provider, selecione GitHub e informe o Client ID e o Client Secret. Salve.
  6. Abra https://SEU-DOMINIO/admin/, clique no login GitHub e autorize o aplicativo. Se sua organização exigir aprovação de aplicativos OAuth, o administrador precisará autorizá-lo.
  7. Altere um campo simples, salve/publique, aguarde o deploy ficar concluído no Netlify e recarregue o site. Este é o teste final da configuração.

Guarde o Client Secret somente na configuração do Netlify. Não o coloque em arquivos, no repositório ou no chat. Para incluir outro editor, adicione-o ao repositório com acesso de escrita; para revogar acesso, remova essa permissão.

A versão anterior utilizava Netlify Identity/Git Gateway. O Git Gateway está descontinuado e não é recomendado para novas configurações, por isso esta reconstrução usa o backend GitHub documentado pelo Decap. A conta GitHub pode utilizar senha, autenticação de dois fatores ou passkey.

3. Trocar ou ajustar as logos

  1. Entre em /admin/ e abra Configurações Globais e Identidade → Logo, slogan, menus, rodapé e rótulos.
  2. No campo Logo PROINC — enviar imagem, escolha uma nova imagem na biblioteca ou envie do computador. A logo fornecida já está selecionada.
  3. Preencha a descrição da logo para acessibilidade.
  4. Ajuste Largura da logo PROINC e Altura da logo PROINC. O padrão é 144 × 144 px. O site mantém a proporção e adapta o tamanho no celular.
  5. Se quiser uma segunda logo, use Logo da instituição — opcional e seus campos de tamanho. Sem imagem, o texto UNIMAM permanece.
  6. Publique e aguarde o novo deploy. Para voltar a uma logo textual, limpe o campo de imagem e edite Texto da logo principal.

A logo anexada foi preservada sem redesenho. Como o arquivo é quadrado e possui margem branca, esses espaços fazem parte da imagem. O painel muda o tamanho de exibição; ele não remove fundo nem recorta a arte. Para um encaixe mais compacto, envie uma versão com margens menores. Use PNG transparente, JPEG ou WebP; procure manter arquivos leves.

4. Personalizar o carrossel

  1. Abra Banner Rotativo (Carrossel). Edite um banner ou clique em criar uma entrada.
  2. Preencha título, descrição, etiqueta, texto do botão e link. Para levar à seção de seleção, use #processo-seletivo; para outra página, use o endereço completo.
  3. Escolha Apresentação: só texto; imagem ao lado; imagem de fundo com texto; ou só imagem.
  4. Envie uma imagem e escreva sua descrição. Para fundo, uma imagem horizontal de aproximadamente 1600 × 600 px costuma facilitar o enquadramento. O campo Enquadramento define centro, topo, baixo, esquerda ou direita.
  5. Em imagem de fundo, ajuste o Escurecimento (%) para manter o texto legível. No modo só imagem, a imagem inteira vira link quando há um endereço no botão.
  6. Defina Ordem de exibição: números menores aparecem primeiro. Desmarque Publicado para ocultar sem apagar.
  7. Para mudar o intervalo ou desligar a rotação automática, vá às Configurações Globais. O visitante pode pausar a rotação; a preferência de movimento reduzido é respeitada.

Sem imagem, o banner apresenta o texto. Com apenas um banner, os controles de rotação desaparecem. Sem banners publicados, a área não aparece.

As notícias mais recentes aparecem primeiro. Listas podem ser reordenadas no editor. Os avisos de exemplo podem ser removidos pelo painel após substituir os dados fictícios. Os textos iniciais continuam demonstrativos; a logo é a que você enviou.

Âncoras disponíveis: #inicio, #noticias, #objetivos, #coordenacao, #orientadores, #bolsistas, #voluntarios, #projetos, #producao, #processo-seletivo, #editais, #formularios e #contato. Menus omitem links para seções ocultas; confira os botões dos banners se ocultar a seção de destino.

Em Processo Seletivo → Coluna lateral — resultados e editais, envie PDFs, edite títulos e observações e arraste os itens para ordenar. As entradas iniciais estão identificadas como exemplos e sem PDF: substitua-as ou remova-as. Em Configurações Globais, você também pode editar a chamada abaixo do banner, desligar a coluna direita e escolher entre seções expansíveis e abertas. Os links dos menus abrem automaticamente a seção expansível de destino.

O painel controla conteúdo e opções de aparência. Redes sociais do cabeçalho e o botão flutuante de WhatsApp também ficam em Configurações Globais. Alterar a estrutura de componentes ou criar um tipo de seção inteiramente novo exige desenvolvimento. Arquivos enviados ao site, como PDFs e imagens, são públicos depois da publicação.

6. Se algo não funcionar

  • O painel informa que falta conectar o projeto: confira GITHUB_REPOSITORY e faça novo deploy. Como alternativa, substitua SEU_USUARIO/SEU_REPOSITORIO em admin/config.yml.
  • Erro no login: confirme callback, provedor OAuth no Netlify, acesso de escrita ao repositório e eventuais permissões da organização GitHub.
  • Editei e não mudou: confira se publicou/salvou, verifique a branch main, aguarde o deploy e recarregue. Veja o log se o deploy falhar.
  • Imagem antiga: envie o novo arquivo com outro nome e selecione-o no campo correspondente. Verifique se realmente publicou a mudança.
  • Logo pequena: aumente o tamanho no painel; se continuar pequena, a margem branca está dentro do arquivo.
  • Notícia/banner sumiu: confira Publicado; confira também a visibilidade da seção.
  • Admin funciona, mas o site está vazio: confirme build node build.mjs e publicação dist. Não publique a pasta admin como raiz.

Arquivos e verificação

data/ guarda as seções; content/, os banners e notícias; assets/, as imagens e PDFs. render.mjs gera as tags HTML. index.html é uma prévia gerada e será refeito a cada build. Use o CMS para conteúdo. O ZIP inclui código, configuração e este guia.
